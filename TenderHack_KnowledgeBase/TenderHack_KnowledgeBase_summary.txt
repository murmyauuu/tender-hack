TENDER HACK — БАЗА ЗНАНИЙ

Что это такое

Это готовый локальный слепок базы знаний для AI-помощника по Порталу поставщиков. Мы собрали в одном месте два типа официальных источников:

1. Документы, которые предоставил организатор хакатона.
2. Публичная база знаний самого Портала поставщиков zakupki.mos.ru.

В финальной SQLite-базе эти два источника разделены полем source_type:

organizer_pdf
portal_knowledge_base_api


1. Откуда взялась информация organizer_pdf

Организатор предоставил официальные инструкции по работе с Порталом поставщиков, в том числе инструкции для поставщиков, заказчиков и материалы по отдельным процессам.

Мы извлекли текст этих документов, разбили его на небольшие смысловые фрагменты и записали их в базу.

Это сделано потому, что AI-агенту неудобно каждый раз читать огромный PDF целиком. Вместо этого он сможет находить только нужный фрагмент документа.

Для каждого фрагмента сохраняется информация вроде:

source_name
page_start
page_end
title
content

После очистки и удаления дублей в финальной базе осталось:

941 фрагмент из документов организатора.


2. Откуда взялась portal_knowledge_base_api

В официальной инструкции Портала мы нашли раздел «Центр поддержки пользователей» и полноценную базу знаний со статьями.

Сначала мы пытались автоматически обходить страницы:

zakupki.mos.ru/knowledgebase/...

Но такой способ оказался медленным и нестабильным.

После этого мы исследовали сетевые запросы, которые делает сам официальный сайт Портала, и обнаружили официальный API базы знаний.

Один из основных запросов:

GET
https://zakupki.mos.ru/newapi/api/KnowledgeBase/GetArticlesBySectionType?sectionType=general

Также используется отдельный endpoint для популярных вопросов:

GetQuestionsBySectionType

Благодаря этому нам больше не нужно было открывать сотни страниц браузером по одной.


3. Что возвращает API

API возвращает уже структурированную базу знаний:

Категория
↓
Сервис / подтема
↓
Статьи

Например:

Личный кабинет пользователя
↓
Сертификат ЭП
↓
Как прикрепить электронную подпись?

В данных статьи присутствуют поля вроде:

categoryName
serviceName
id
staticId
largeName
previewText
detailText
instructionOperator
chatBots
selfServicePortal

То есть Портал в некоторых случаях уже отдельно хранит:

- полный текст статьи;
- инструкцию для оператора;
- текст для чат-бота;
- текст для self-service.


4. Какие разделы были выгружены

Мы собрали статьи по нескольким sectionType:

general — 62 уникальные статьи
supplier — 252
instruction — 159
customer — 45

Эти числа нельзя складывать, потому что одна статья может одновременно относиться сразу к нескольким разделам.

После удаления повторов получилось:

483 уникальные статьи Портала поставщиков.


5. Почему в базе 527 фрагментов из Портала, а статей 483

Некоторые статьи длинные.

Для будущего RAG-поиска длинные статьи были разбиты на несколько небольших смысловых частей — chunks.

Например:

Статья
↓
chunk 1
chunk 2
chunk 3
chunk 4

Поэтому:

483 уникальные статьи
↓
527 поисковых фрагментов


6. Что получилось в итоге

Финальная база содержит:

941 фрагмент из PDF организатора
+
527 фрагментов из официальной базы знаний Портала
=
1468 уникальных поисковых фрагментов


7. Основные файлы

knowledge_base_FINAL.sqlite

Это основная SQLite-база знаний.

SQLite удобна тем, что вся база хранится в одном файле. Для неё не нужен отдельный сервер базы данных.

Файл можно просто скопировать другому участнику команды, и у него будет точно такая же база.


knowledge_base_FINAL.jsonl

Это та же информация в формате JSONL.

Каждая строка файла — отдельный JSON-объект.

JSONL удобно использовать для:

- embeddings;
- RAG;
- ML;
- Python-скриптов;
- построения семантического поиска.


api_report.json

Это технический отчёт о сборке базы.

Он показывает:

- сколько статей найдено;
- какие разделы использованы;
- сколько записей пришло из документов организатора;
- сколько получилось финальных фрагментов;
- какие итоговые файлы были созданы.


8. Что НЕ входит в эту базу

Файл:

Выгрузка СТП за 2026.xlsx

НЕ использовался как источник знаний.

Мы сознательно не смешивали ответы операторов из реальных обращений с официальной базой.

Официальными источниками ответа являются:

- инструкции организатора;
- официальные статьи Портала поставщиков.

А «Выгрузка СТП за 2026.xlsx» будет использоваться отдельно для:

- анализа обращений;
- маршрутизации;
- классификации;
- выявления частых проблем;
- оценки операторов;
- тестирования Planner.


9. Как база будет использоваться Planner

Логика системы:

Пользователь
↓
Planner
↓
поиск по knowledge_base_FINAL
↓
TOP-3 наиболее релевантных знания
↓
достаточно ли информации?

Если ДА:
Planner формирует ответ на основании базы знаний и отвечает пользователю.

Если НЕТ:
Planner определяет, на какую линию поддержки направить обращение:

1 линия
2 линия
3 линия


Пример:

Пользователь:
«Как прикрепить электронную подпись к аккаунту?»

Поиск по базе должен вернуть примерно:

1. Как прикрепить электронную подпись?
2. Как изменить электронную подпись
3. Как прикрепить или изменить ЭП...

После этого Planner понимает, что информации достаточно, и отвечает из базы знаний.


10. Что передавать сокомандникам

Для передачи команде достаточно создать архив:

TenderHack_KnowledgeBase.zip

и положить в него:

knowledge_base_FINAL.sqlite
knowledge_base_FINAL.jsonl
api_report.json
README.txt

Сокомандникам НЕ нужно:

- повторно парсить zakupki.mos.ru;
- запускать Chromium;
- устанавливать Playwright;
- отключать VPN;
- заново собирать 483 статьи.

Они получают уже готовую локальную базу.


11. Как открыть базу на другом ноутбуке

Для просмотра:

1. Установить DB Browser for SQLite.
2. Открыть knowledge_base_FINAL.sqlite.
3. Перейти во вкладку Browse Data.
4. Выбрать таблицу documents.

Для использования в Python:

import sqlite3

conn = sqlite3.connect("knowledge_base_FINAL.sqlite")

rows = conn.execute("""
SELECT title, topic, subtopic, content
FROM documents
LIMIT 10
""").fetchall()

for row in rows:
    print(row)


12. Краткая формулировка для команды / защиты

Мы сформировали локальную базу знаний из двух официальных источников: инструкций, предоставленных организатором хакатона, и актуальной публичной базы знаний Портала поставщиков.

Статьи Портала были получены через официальный API самого сайта, после чего были очищены, структурированы по темам и подтемам, дедуплицированы и разбиты на поисковые чанки.

Итоговая база содержит 1468 уникальных фрагментов: 941 из материалов организатора и 527 из 483 уникальных статей Портала.

Файл «Выгрузка СТП за 2026.xlsx» в базу знаний не включался и будет использоваться отдельно для анализа обращений, маршрутизации и оценки работы поддержки.

Финальная база хранится в переносимых форматах SQLite и JSONL и может быть без повторной сборки запущена на ноутбуке любого участника команды.
