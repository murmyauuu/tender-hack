## 3. Shortlist дефектов KB (для C02)

Отсортировано по влиянию на ответы. Все счётчики воспроизводятся скриптом.

### D1. Регламент отсутствует в KB — 0 чанков (критично)

`Регламент_информационного_взаимодействия-4.pdf` лежит в репозитории, но в KB его нет: 0 записей с `source_name`/`source_key`/`title`, содержащими «реглам»; в 1 чанке он лишь упомянут текстом. По §10 Регламент — **высший приоритет для нормативных утверждений**. Сейчас нормативные ответы опираться не на что.

**PDF пригоден к загрузке:** 57 страниц, PDF 1.7, не зашифрован, текстовый слой есть (7838 операторов Tj/TJ в выборке). C02 может его нормализовать без OCR.

### D2. `source_url` — это URL API коллекции, а не статьи (критично для citations)

Все 527 портальных записей несут один из четырёх URL вида
`https://zakupki.mos.ru/newapi/api/KnowledgeBase/GetArticlesBySectionType?sectionType=<general|supplier|customer|instruction>`
(230 / 192 / 60 / 45 записей). Это endpoint выгрузки, **не адрес статьи**. §10.6 прямо запрещает выводить URL статьи из URL API. Отдельного per-article URL в снимке нет. Ссылку на статью в ответе выдавать нельзя; `article_id` из `source_key` — единственный реальный идентификатор.

### D3. `updated_at` — одна константа на весь портальный срез (критично)

Все 527 записей: `16.07.2026 15:01:16` — один timestamp, т.е. момент выгрузки/сборки, а не дата актуальности статьи. §10.6 запрещает выдумывать даты актуальности. Поле нужно трактовать как `collected_at`, а актуальность статьи — `unknown`. Приоритет по свежести на этих данных не строится.

### D4. `audience` смешивает роль и тип документа

Фактические значения: `supplier` 891, `customer` 314, **`instruction` 192**, `general` 51, `supplier,customer` 20. §10.4 прямо говорит: «instruction не является пользовательской ролью». 192 записи имеют в поле роли значение, которое ролью не является; `general`/`unknown` не означает «все роли». Нужен отдельный `audience_raw` + производная роль.

### D5. Служебные фрагменты: оглавления и номера страниц

| Класс | Записей |
|---|---|
| `content` — только номер страницы (напр. `"2"`, `"3"`) | **17** |
| Оглавление по точкам-лидерам (`.....  29`) | 27 |
| `title` = «Содержание»/«СОДЕРЖАНИЕ» | 21 |
| `content` короче 40 символов | 19 |
| **Объединение «жёсткого мусора»** | **44 записи** |

Минимальный `content` в `organizer_pdf` — **1 символ**. Примеры: `title='Содержание'`, `content='2'`; `title='1. Термины и сокращения'`, `content='4'`. §10.2 требует удалить такие фрагменты с указанием причины.

### D6. 776 чанков ссылаются на рисунки, которых в KB нет

776 из 1468 (53 %) содержат «Рисунок N» / «Рис. N». В PDF суммарно 1416 встроенных изображений, в KB не перенесено ни одного. Часть чанков состоит **только** из подписей: напр. `content='26\n\nРисунок 35 – Страница «Обучение в сфере закупок»'`. §10.7 — отсутствующие скриншоты не считаются прочитанными; §10 Gate — существенный missing attachment ведёт в `ESCALATE`/`MISSING_ATTACHMENT`. Ещё 23 чанка ссылаются на «Приложение»/«см.».

### D7. Чанкинг привязан к странице, а не к смыслу

Ни один из 941 PDF-чанков не пересекает границу страницы (`page_start == page_end` во всех 941). 941 чанк на 830 страниц ≈ 1.13 чанка/страницу; 65 страниц разбиты на >1 чанк (максимум 6). Ориентир §10 — child 220–400 токенов, overlap 30–50 внутри секции, parent 600–1000, восстановление parent-статьи. Сейчас: **parent/секции нет, overlap нет, разрыв ровно по вёрстке**. Раздел, идущий через разрыв страницы, гарантированно расщеплён, и условие может быть оторвано от действия. Для портальных записей parent восстановим (`article_id` из `source_key`), для PDF — только по странице.

### D8. `title` часто не заголовок

27 записей имеют `title` = имя файла (`Инструкция по работе с Порталом для поставщика.pdf`). Остальные `title` — первая строка фрагмента, часто обрезанное предложение (`'Подраздел «Котировочные сессии» предназначен для перехо'`) или пункт оглавления с точками. Повторяющиеся заголовки: `Наименование поля` ×24, `Фильтр` ×19. §10 «Поиск» требует включать заголовок в embedding — при таких `title` это вносит шум, а не сигнал.
