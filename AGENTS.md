# AGENTS.md — правила работы агентов TenderHack

Этот файл действует для всего репозитория. Каноническая спецификация: `TenderHack_UNIFIED_SPEC_v2.1_prefilled.md`. При конфликте со старыми именами или внутренними ссылками применяйте v2.1 и явное задание текущего TASK_ID.

## Главное правило

Одна задача с ID (A00, B01, C03 и т. п.) выполняется в одном новом чате. Выполните только этот ID, создайте commit или patch и handoff, затем остановитесь. Следующий ID запускается в новом чате.

Перед началом проверьте:

1. TASK_ID, BASE_SHA, ветку и рабочий каталог.
2. Все обязательные зависимости задачи имеют принятые commits/handoff.
3. Входные данные реально существуют. Не создавайте синтетическую замену, выдавая её за real.
4. Профиль машины подходит. GPU-команды выполняются только в согласованный слот на профиле G.
5. Рабочее дерево чистое: git status --short.

## Владение файлами

| Владелец | Разрешённые пути |
|---|---|
| A / Артём | contracts, backend, tools, infra, config/runtime, корневые конфигурации/lock/README, docs/integration и свои content/coordination |
| B / Стас | frontend, evaluation/annotations/stas и свои content/coordination |
| C / Эдуард | knowledge, config/knowledge и свои content/coordination |
| D / Егор | evaluation кроме annotations/stas, reports, presentation, docs/process и свои content/coordination |

data/raw неизменно. var, artifacts, веса и индексы — локальные результаты вне Git. Владение означает право редактирования; читать и проверять чужой модуль можно.

Замороженный bootstrap-контракт C0 имеет версию `2.0.0-c0`; канон моделей находится в `contracts/python`, а OpenAPI и JSON Schema генерируются из него командой из README.

Не меняйте чужие файлы «по пути», не перемещайте чужие модули, не делайте форматирование всего репозитория. Воспроизводимый дефект передайте владельцу. Для изменения общего контракта создайте CR по шаблону docs/templates/CR_TEMPLATE.md; канонический контракт меняет только A.

## Архитектурные ограничения

- Один локальный runtime-узел и один последовательный тяжёлый GPU-участок.
- На одну обработку 0–1 генеративный вызов; автоматического повторного generation нет.
- В runtime нет автономной мультиагентной системы, LLM-критика, reranker, внешнего AI/search API и операторского кабинета.
- Исторические ответы, operator reply и feedback не являются trusted KB.
- Profanity проверяется до routing/retrieval/generation.
- Неизвестное сохраняется как null/unknown; факты, URLs, даты, источники и результаты тестов не выдумываются.
- Mock/fixture маркируется как mock. PASS ставится только по фактической проверке.
- Final-набор не раскрывается разработчикам до RC.

## Git и передача

Работайте от принятого BASE_SHA. Рекомендуемая ветка: task/<task-id>-<slug>. Не коммитьте напрямую в main, кроме интегратора A при приёмке.

Завершение задачи:

1. Выполните релевантные проверки и сохраните фактический вывод.
2. Создайте docs/coordination/<owner>/<TASK_ID>-handoff.md по шаблону.
3. Зафиксируйте только разрешённые файлы.
4. Передайте result SHA или patch, handoff и артефакты с manifest/hash.
5. Остановитесь, не начинайте следующий ID.

Нельзя удалять тесты ради зелёного результата, скрывать ошибку или называть fixture реальным E2E. Секреты, cookie, токены и service key не попадают в Git, frontend, handoff и отчёты.
